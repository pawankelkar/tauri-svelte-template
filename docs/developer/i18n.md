# Internationalisation

## Setup

i18next is configured in `src/lib/i18n/config.ts` with static JSON imports —
no runtime fetch:

```ts
import en from '../../../locales/en.json'

const resources = {
  en: { translation: en },
}
```

Fallback language is `en`. Interpolation escaping is off (Svelte already
escapes output).

## Reactive `t()` helper

`src/lib/i18n/t.svelte.ts` exports a `t(key, options?)` function that is
reactive to language changes:

```ts
let tick = $state(0)
i18n.on('languageChanged', () => { tick++ })

export function t(key: string, options?: Record<string, unknown>): string {
  void tick
  return i18n.t(key, options)
}
```

Use `t()` in components instead of calling `i18n.t()` directly — it ensures
Svelte re-renders when the language changes.

## Language initialisation

`src/lib/i18n/language-init.ts` runs during the boot sequence:

1. If a saved language preference exists and is available, use it
2. Otherwise, read the system locale via `@tauri-apps/plugin-os`'s `locale()`
3. If the system locale's language code matches an available language, use it
4. Otherwise, fall back to `en`

## RTL support

The `languageChanged` callback in `config.ts` sets
`document.documentElement.dir` to `'rtl'` for Arabic, Hebrew, Farsi, and
Urdu, and `'ltr'` for everything else.

## Native menus

`src/lib/menu.ts` subscribes to `i18n.on('languageChanged')` and rebuilds
the entire native menu bar. Menu item labels come from `i18n.t(labelKey)`,
so switching language updates every menu label.

## Locale keys

All keys live in `locales/en.json`. The file is flat (no nesting), with
dot-separated prefixes for grouping:

```
commands.toggleTheme     → "Toggle Theme"
preferences.nav.general  → "General"
preferences.privacy.offlineLabel → "Offline Mode"
```

## Adding a locale

1. Create `locales/<code>.json` with the same keys as `en.json`
2. Import it in `src/lib/i18n/config.ts` and add to `resources`:
   ```ts
   import fr from '../../../locales/fr.json'
   const resources = { en: { translation: en }, fr: { translation: fr } }
   ```
3. Add its display name to `languageLabels`:
   ```ts
   export const languageLabels: Record<string, string> = {
     en: 'English',
     fr: 'Français',
   }
   ```
4. A unit test in `config.test.ts` asserts `resources` and `languageLabels`
   have the same keys — it will catch a missing entry.
