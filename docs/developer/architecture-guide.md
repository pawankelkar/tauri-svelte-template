# Architecture Guide

## Project layout

This is a single-package Tauri v2 + Svelte 5 application. The frontend and
backend live side by side:

```
src/                          Frontend (TypeScript, Svelte 5)
  main.ts                     Entry point — flash-free boot, mounts App
  App.svelte                  Root component — boot sequence, close handshake
  quick-pane-main.ts          Second Vite entry for the Quick Pane window
  app.css                     Tailwind v4 + theme variable import
  lib/
    commands/                 Command registry, palette state, command modules
    components/               UI components (layout, preferences, demo, shadcn ui/)
    hooks/                    Reactive helpers (use-platform, is-mobile)
    i18n/                     i18next config, language init, reactive t()
    quick-pane/               Cross-window event bridge
    stores/                   Persisted state (preferences, app-state, theme, ui, dirty)
    utils/                    debounce-persist, platform helpers
    bindings.ts               GENERATED by tauri-specta — never hand-edit
    tauri-bindings.ts          Re-export + unwrapResult()
    shortcuts.ts              Shortcut parsing, normalisation, keydown handler
    menu.ts                   Native menu bar built in JS
    context-menu.ts           Native right-click menus
    platform-strings.ts       Platform-aware display labels and shortcut formatting
    logger.ts                 Frontend logging (dev: console, prod: backend)
    lifecycle.ts              Store flushing, quit path, unsaved-changes gate
    diagnostics.ts            Plain-text formatter for diagnostics reports

src-tauri/                    Backend (Rust)
  src/
    lib.rs                    Plugin chain, setup(), close handshake, RunEvent
    bindings.rs               specta command registration + TS export
    types.rs                  AppPreferences, PersistedAppState, ShortcutPurpose
    tray.rs                   Tray icon — show/focus on click, Show/Quit menu
    commands/                 json_store, preferences, app_state, global_shortcut,
                              quick_pane, recovery, crash_reporter, diagnostics,
                              lifecycle, demo
  capabilities/               Per-window permission grants
  tauri.conf.json             App config (+ platform overrides)
```

The `$lib` alias in `vite.config.ts` maps to `src/lib`, so imports read
`$lib/stores/theme.svelte` rather than relative paths.

## Two Vite entry points

The main window and the Quick Pane are separate HTML documents, each mounting
its own Svelte app. `vite.config.ts` declares both in `build.rollupOptions.input`:

```ts
input: {
  main: path.resolve(__dirname, 'index.html'),
  'quick-pane': path.resolve(__dirname, 'quick-pane.html'),
},
```

In dev, Vite serves both from the project root. In production, Rollup outputs
two bundles. See [Quick Panes](quick-panes.md) for the full multi-window story.

## Boot sequence

`src/main.ts` runs synchronously before the first paint:

1. `paintFromHint()` — reads `localStorage['ui-theme']`, applies `.dark` class
2. `mount(App, ...)` — Svelte mounts `App.svelte`

`App.svelte`'s `onMount` then runs the async chain:

1. `initSquareCorners()` — fullscreen listener for corner-radius toggle
2. `initTheme()` — `matchMedia` listener for system scheme changes
3. `initQuickPaneBridge()` — listens for `quick-pane-submit` events
4. `initPreferences()` + `initAppState()` — load from disk in parallel
5. `reconcileTheme()` — authoritative preferences override the localStorage hint
6. `applyWindowEffects(prefs.windowEffects)` — native vibrancy IPC, before the
   window is shown so there is no opaque→translucent pop
7. `initializeLanguage(prefs.language)` — set i18next language
8. `initCommands()` — register all commands, wire keydown handler, build menus
9. `cleanupOldRecoveryFiles()` — purge crash data older than 7 days
10. `checkForRecentCrash()` — show a warning toast if the app crashed recently

The main window is created with `visible: false` in `tauri.conf.json`.
`App.svelte` calls `appWindow.show()` + `appWindow.setFocus()` after mount,
so the user never sees an unstyled flash.

## Single dispatch path

Keyboard shortcuts, the command palette, and native menus all dispatch through
`executeCommand(id)` in `src/lib/commands/registry.svelte.ts`. No command body
is duplicated across input sources.

## Svelte 5 patterns

**Function-based stores** — stores expose plain functions (`getPreferences()`,
`setPreference()`, `initPreferences()`) backed by module-level `$state` and
`$effect`. No class-based stores.

**`$state.snapshot()` before IPC** — Svelte 5 rune proxies do not serialise
over the Tauri IPC bridge. Every `invoke()` / `commands.*` call that sends
reactive state must wrap it with `$state.snapshot()` first. An ast-grep rule
(`snapshot-before-ipc.yml`) enforces this.

**tauri-specta bindings** — Rust commands are never called via raw `invoke()`.
All IPC goes through the generated `$lib/bindings.ts` and the typed re-export
in `$lib/tauri-bindings.ts`, which provides `unwrapResult()` for the
`Result<T, String>` envelope.

## Monorepo promotion

`lib/components/ui`, `stores`, and `utils` are cleanly separated already.
Promoting to a pnpm workspace later is mechanical: move each to its own
`packages/` directory, add a `package.json` with the appropriate exports, and
update import paths.
